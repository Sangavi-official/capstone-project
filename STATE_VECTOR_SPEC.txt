DESIGN RULES ENFORCED IN THIS VERSION
---------------------------------------
1. Each index has exactly ONE data source. No index is ever the
   sum, product, or blend of two different signals.

2. [8] recon_attempts is now independent — it no longer absorbs
   abuse_score. This was the corrupted index identified in audit.

3. [10] and [11] are NEW dedicated slots for abuse_score and
   attck_score. Previously these were fetched and discarded
   (attck_score) or saturated to 1.0 by a broken denominator
   (abuse_score). Both are now properly normalized AND properly
   written into the state the agent actually observes.

4. All four live API scores ([5],[6],[10],[11]) are fetched
   EXACTLY ONCE at environment construction (__init__), never
   inside reset() or step(). This prevents API rate-limit
   exhaustion during 100,000-step training runs.

5. Normalization denominators were corrected based on real
   observed API response magnitudes (see audit below), not
   guessed values.

NORMALIZATION FIXES (WITH JUSTIFICATION)
-------------------------------------------
AbuseIPDB:
  OLD: limit=100 in API call, divide by 100  -> always saturates to 1.0
  NEW: limit=10000 in API call, divide by 10000 -> real headroom

MITRE ATT&CK:
  OLD: keywords = health, hospital, medical, iot, scada, ics
       -> "iot"/"ics" matched ~25% of the ENTIRE framework (151/600)
  NEW: keywords = medical device, healthcare, hospital, patient,
       clinical -> genuinely healthcare-specific subset only
       (expected real count: single digits to low tens, not 150+)
  NEW denominator: divide by 30 (realistic ceiling for a true
  healthcare-specific technique count, leaves real headroom)
